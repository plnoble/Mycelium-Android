## 代码审查（只看关键路径）

- **出网网关**：白名单只放行更新用的三个 GitHub 域名和用户保存过的服务地址；明文 http 只在调试包、而且只对 `127.0.0.1` 放行；不跟随重定向；地址里不许带账号。审计记录存发送正文和 token 用量，不存请求头，所以 key 进不了记录。
- **拉取模型**：`GET {地址}/models` 走网关、记审计；只读取返回列表里每个模型的名字（`data[].id`）并去重；空列表、401、超时、格式不认识都有中文提示，拉取失败不会清掉已保存的模型。
- **密钥和对话库**：key 用 Android Keystore 的 AES-GCM 包装后保存，界面只显示末 4 位；对话库用 SQLCipher 加密，口令也由 Keystore 保护。源码里没有日志输出。
- **接口对齐**：云端回答实现了 `:model-api` 的 `ChatModel`，`CloudChat` 只依赖这个接口，以后本地模型可以直接接上。「我的」里的模型页已按「本地」「云端」分组（P2-1 审核建议 3）。
- **测例修正 `66e3a5a`**：原来的设备测例把库文件按 ISO-8859-1 解码后直接找中文原句，这样永远找不到，等于什么都没查。改成按字节比较，并加了「文件开头不能是明文 SQLite 头」的断言；JVM 上的对照测例证明，同样的比较方法在未加密的库里确实能找到。改得对。

## 统筹补改（`7df0b8b`）

1. **更新检查只能走网关**：`:net` 里原来有一个公开的 `httpGet`，它直接发请求，不经过白名单和审计。`GitHubReleaseClient()`、`UpdateManager()` 不传参数时默认用它。应用里调用时传的是走网关的实现，所以目前没出问题；但只要有人不传参数直接用，检查更新就会绕过网关，违反「所有出网请求走网关并留审计」。已删除 `httpGet`，两处构造函数也去掉了默认值。测试本来就是显式传参，不受影响。
2. **拉取失败的提示改成白话**：连不上时原来会把底层报错原样显示，例如「unexpected end of stream on com.android.okhttp.Address@7e60d939」（截图 17）。现在改成「连不上这个地址，请检查接口地址和网络后再试」。
