**结论：不通过。** 方案方向可行，但当前存在缓存归属漏洞，且目标 Qwen3.5 的底层状态限制可能使复用始终退回整段重读；测试计划也不足以发现这些问题。以下前三项最关键。

统筹 3.1 已批准的五项选择——含模型 ID、新会话第二轮重读、按真实公共前缀复用、多一次 tokenize、`promptMillis` 新口径——均应保留。E、D 已是本包必做内容，不能再列为待定。此次仅静态只读审核，未修改文件、未跑 Gradle。

**必修项清单**

1. **目标模型可能根本无法按此方案提速。**

   **位置：** [PLAN.md:80](docs/reviews/2026-10-19-P2-1c/PLAN.md:80)、第 6 节内存评估；`engine.cpp:101`。

   **问题：** 固定版本的 Qwen3.5 使用混合状态，不能把它当成普通 Transformer KV 任意裁尾。当前上下文沿用默认 `n_rs_seq = 0`；生成后，循环状态已经推进到回答末尾，再裁回提示公共前缀会返回 false。依据是固定提交的[默认参数](llm/vendor/llama.cpp/src/llama-context.cpp:3757)和[循环状态删除实现](llm/vendor/llama.cpp/src/llama-memory-recurrent.cpp:200)，混合内存也会传播这个失败。

   **为什么必修：** 退回 `clear` 保证正确性，但可能让目标模型每轮仍读 1500 token，完全没有解决本包的实际问题；输出一致性测试却照样通过。

   **怎么改：** 在方案最前面补目标模型的可行性验证，确认生成后能恢复到**真实公共前缀边界**。需要时设计循环状态检查点／受支持的回退机制，明确边界不足时的全清策略，并重新评估内存；不能仅开启少量快照就假定覆盖任意回退距离。验收必须要求目标模型实际出现非零复用及实读量下降，不能把始终 fallback 算作完成。

2. **无键调用保留旧 Kotlin 归属，会使归属与实际 KV 脱节。**

   **位置：** [PLAN.md:73](docs/reviews/2026-10-19-P2-1c/PLAN.md:73)、第 3.4 节 null 行、第 4 节 `noCacheKeyNeverReusesAndLeavesTheCacheAlone`。

   **问题：** 路径是：带键 A 建缓存 → 无键 B 全清并生成 → 再调用 A。Kotlin 仍记着 A，但原生缓存已经属于 B。只要提示存在公共前缀，原生二次 LCP 仍可能允许使用 B 留下的前缀。

   **为什么必修：** 二次 LCP 能阻止不同 token 的错误复用，但不能证明缓存属于 A；“无键完全不影响缓存状态”在单一原生上下文上不成立。

   **怎么改：** 无键调用进入时清除 Kotlin 的 owner 和缓存提示，原生照旧全清全读；后续带键调用必须重新建缓存。将测试改为 `A → null(B) → A` 最后一轮 `reuseTokens == 0`，并覆盖 B 成功、停止和失败。无键调用本身的输出行为仍可保持不变。

3. **字面量 `pending` 不能区分不同临时会话。**

   **位置：** [PLAN.md:48](docs/reviews/2026-10-19-P2-1c/PLAN.md:48)、第 4 节炉边键测试。

   **问题：** 同人物、同模型、同模式下，所有未落库会话共用一个键。第一轮完成后立即点“新对话”，上一轮缓存仍标为 `pending`；测试模式退出再进入也会重复这个键。现有导航只停止任务，不会自动卸载或清缓存。

   **为什么必修：** 违反“换会话整段重读”的隔离要求。接受第二轮换真实 ID，并不等于允许不同临时会话共用身份。

   **怎么改：** 给每个临时会话分配仅驻内存的唯一标识，在新对话、重新进入测试会话等边界更新，并冻结进 `Turn`。首次落库后仍切到真实 ID，因此保留统筹批准的第二轮重读行为，无须提前创建数据库会话。补“同人物连续新建两段会话”和“退出再进入测试模式”的实际调用测试。

4. **异常清理与新增 tokenize 的取消边界没有闭合。**

   **位置：** [PLAN.md:104](docs/reviews/2026-10-19-P2-1c/PLAN.md:104)；[LocalModelEngine.kt:143](llm/src/main/java/com/xavierxia/mycelium/llm/LocalModelEngine.kt:143)；`engine.cpp:131、136、171、175`。

   **问题：** 当前原生有多处直接 `return nullptr`，不会经过 C++ `catch`。此外，`llama_decode` 中止／严重失败可能留下已处理的状态，不能仅凭“提示曾读完”断定缓存可用。新增 tokenize 若单独套一次 `runNative`，随后 generate 的 `begin()` 会再次清停止标志。

   **为什么必修：** 会留下旧元数据对应新／不完整内存的状态，或吞掉 tokenize 与 generate 之间的停止请求。

   **怎么改：** 明确事务边界：在同一 `gate`、一次 `runNative/begin` 内完成 tokenize、比较和生成；取消时先 stop、join，再作废，最后释放锁。原生统一处理所有提前返回和异常出口，失败时同时重置 `cachedPrompt/promptComplete` 并清内存。只有确认内存仍有效的正常停止才可保留；decode 中止或状态不明时保守作废。加载失败、同模型重新加载、卸载也须覆盖。

5. **前缀边界和七项 JNI 契约存在互相冲突的定义。**

   **位置：** [PLAN.md:68](docs/reviews/2026-10-19-P2-1c/PLAN.md:68)、80、115、136、186 行。

   **问题：** “最多复用 `tokens.size - 1`”与“全等时不复用、整段读”冲突；同提示测例又要求复用完整 LCP。原生 `min(...)` 没有下界保护。旧五项返回的“按默认处理并 `error`”也不是确定的契约。

   **为什么必修：** 实现者会得到不同的全等行为；负数 reuse 可进入非法索引路径；旧数组静默补值可能伪造缓存完成状态。

   **怎么改：** 明确定义，例如有效提示下统一使用  
   `reuse = max(0, min(requested, nativeLcp, count - 1))`，全等时重读最后一个 token；无效长度直接失败。确认 `seq_rm(0, reuse, -1)` 删除的是位置 `[reuse, ∞)`，保留 `[0, reuse)`；false 后全清并从位置 0 开始。七项返回严格校验长度、计数范围及 `count` 与 tokenize 结果的一致性，失败即作废，不默默兼容五项。方案列出的两个 `EngineBridge` 假实现确实都要更新。还须增加真实 JNI 调用验证：**编译成功不能证明 JNI 符号和参数 ABI 正确。**

6. **测试计划有多处“只能测转发，却声称测到了原生正确性”。**

   **位置：** [PLAN.md:135](docs/reviews/2026-10-19-P2-1c/PLAN.md:135)、155、165、175 行；[HearthPromptSpeedDeviceTest.kt:68](app/src/androidTest/java/com/xavierxia/mycelium/hearth/HearthPromptSpeedDeviceTest.kt:68)。

   **问题：** 假桥提供的耗时不能验证 C++ 计时边界；实际 `generate` 接收消息字节，并不接收方案所写的 `(tokens, reuseTokens)`。用新提示自己的前缀重建新提示是恒等式，也证明不了旧 KV 正确。现有真机测速不传键、重复同一提示、只数 chunks，不能验证多轮命中或逐字一致。

   **为什么必修：** 全部禁用原生复用、错删 KV、错误计时等实现，都可能在现有计划下全绿。

   **怎么改：** 明确各层证据范围，并补以下判别条件：
   - JVM 用固定 token 向量覆盖中间分歧、全等、缩短、零公共前缀；纯追加样例不能单独识别“总是复用旧长度”的错误。
   - 假桥维护独立的旧状态，断言 `旧状态.take(reuse) + 新提示.drop(reuse)`；只称为决策／契约测试。
   - 圆桌测试捕获 `CloudChat.ask` 实际传入的参数，不能只检查新建默认参数对象。
   - 真机新增带稳定键、真实追加问答的路径，并断言实际复用数大于零；用完全相同的每轮消息分别跑缓存与全清，收集正文比较，不能只比较 chunk 数。
   - 真机覆盖裁剪成功、fallback、停止／异常后的下一轮。明确区分“正确但全读”与“正确且提速”；把原生复用强制改成零时，提速验收必须变红。

7. **统计新口径获批，但仍需明确边界，避免把它当成首字等待时间。**

   **位置：** [PLAN.md:111](docs/reviews/2026-10-19-P2-1c/PLAN.md:111)、第 4 节统计落地。

   **问题：** `promptMillis` 不包含额外 tokenize、模板处理、加载和隐藏思考。它降低不代表“发送到可显示正文”同幅降低。中断的 decode 批次如何计入“实际读 token”也未说明。

   **为什么必修：** 会让性能结论和停止后的统计含义漂移。

   **怎么改：** 文档、日志明确：`promptTokens` 是完整提示；正常完成时 `reused + read == promptTokens`，中断时允许小于。说明失败批次计数是确认完成量还是通过内存位置核实的量。另记录发送到首个可显示正文的耗时及无正文状态。保留现有 `generatedTokens/generationMillis/tokensPerSecond` 的总生成口径，隐藏段统计只追加；现有生成 token 数测试不能改成正文 token 数测试。

8. **E 必须补成可实施的一步，并处理 token 归属、耗时起点和取消统计。**

   **位置：** [PLAN.md:188](docs/reviews/2026-10-19-P2-1c/PLAN.md:188)；[TextStream.kt:24](llm/src/main/java/com/xavierxia/mycelium/llm/TextStream.kt:24)、`LocalModelEngine.kt:122`。

   **问题：** 第 7 节仍写不实现，违反统筹裁定。当前过滤器只有正文输出，没有隐藏段统计；取消时 `runNative` 会抛出，正常路径上的 `lastStats` 赋值不会执行。

   **为什么必修：** 最需要诊断的“长时间隐藏思考后停止”，恰好可能没有统计。字符数、Flow 片段数也不能冒充 token 数。

   **怎么改：** 最小落点是 `TokenCallback/ThinkingFilter/GenerationStats` 加设备日志：按每次原生 token 回调记录 token 身份，让过滤器同时报告隐藏区间，保留跨 token 标签及 UTF-8 的归属信息；明确标记 token、混合正文 token、未闭合段的计数规则。时间用生成阶段的单调时钟，不能从当前 prefill 前的 `onStart` 开始；七项返回可保留，通过扩展回调提供时间信息。取消后的统计在 worker 已退出、仍持锁的收尾中提交，继续传播取消。日志只记数字和必要标志，不打印整段提示或隐藏正文。

   **风险与验证：** 分裂标签、同 token 跨边界、未闭合段及取消收尾最易错。补这些样例，并断言加入统计前后正文逐字相同；记录隐藏段结束时的剩余生成预算。

9. **D 必须明确“20 秒无正文”的作用域和退出条件。**

   **位置：** [PLAN.md:203](docs/reviews/2026-10-19-P2-1c/PLAN.md:203)；`HearthViewModel.startTurn/regenerate/stream`；[HearthSpace.kt:403](app/src/main/java/com/xavierxia/mycelium/hearth/HearthSpace.kt:403)。

   **问题：** 没有起算点、正文定义、旧轮次隔离和测试安排。若依赖 token 回调，prefill 完全无回调时就不会提示。

   **为什么必修：** 可能漏掉最长等待，或在已出字、已停止、已换人物后弹出过期提示。

   **怎么改：** 最小实现是在 ViewModel 为本地轮次设置独立计时任务，阈值常量 `20_000L`；建议从接受该轮开始，包含加载与 prefill。以过滤后出现非空白正文为结束条件，不能以原生 token 到达为准。给 `HearthState` 增加独立提示状态，避免与加载／错误 `notice` 互相覆盖；用 `Turn` 身份和 generation token 防止旧任务更新新页面。首字、完成、停止、失败、导航及清理时取消计时。UI 展示提示并复用现有停止按钮，引导去人物编辑选择云端，不能自动切换或发送。

   **风险与验证：** 发送和重新生成均需覆盖；用可控时钟验证阈值前后、空白输出、首字到达、换会话及取消，不使用真实等待 20 秒的测试。
