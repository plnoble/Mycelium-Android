## 1. 实测：两轮提示的分叉点在哪（2026-10-22 15:1x，红魔真机）

测法：`app/src/androidTest/.../HybridCheckpointDivergenceDeviceTest.kt`，用**真实 Qwen3.5 模板**（引擎自己的
`tokenize`，格式与生成时完全一致），温度 0 真跑一轮拿真实回答，再把两轮提示编成 token 比较：

| 量 | 值 |
|---|---|
| 第一轮提示 token | 1120 |
| 第二轮提示 token | 1275 |
| **最长公共前缀** | **1116** |
| 第一轮公共前缀之后还剩 | **4 个 token**（`248068, 271, 248069`）＝助手角色头 + 换行 + 新起一段 |
| 第二轮同位置开始 | 上一轮真实回答的第一个 token（`96218`，正文「先说结论…」） |
| 回答长度 | 176 字 |

**结论（直接决定落点）**：

- 「读完提示、开始生成之前」这个位置（第一轮 1120）**超出公共前缀 4 个 token**。在那里存检查点，下一轮
  恢复出来的循环层状态就多带了「生成脚手架」那 4 个 token，位置是错的 → **不能用**。
- 可用落点是**用户这一轮文本结束、生成脚手架开始之前**（本例 1116）。它与 1120 之间只差模板给的那几个
  脚手架 token，长度可由「带 / 不带 `add_generation_prompt` 两次 tokenize 的长度差」量出来，**不写死常数**
  （换模型、换模板都对）。

**这个落点的名字按真机证据改过一次（方案审必修项 1，2026-10-23 早）**：原写「助手角色头之前」，但真机把
token 逐个解码出来看（证据见仓库外 `logs\p2-1d-evidence\p2-1d-boundary.txt`）：

| 位置 | token | 解码文本 |
|---|---|---|
| 49 | 248068 | `<think>` |
| 51 | 248069 | `</think>` |
| 44 / 46 | 248046 / 248045 | （空串，特殊 token） |

整段提示的末尾文本是 `…user\n我想先安静。\n\n<think>\n\n</think>\n\n`，砍掉最后 8 个 token 之后停在
`…我想先安静。`。所以：**那两个 token 是思考段的 `<think>`/`</think>`，不是助手角色头**；真正的角色头
是解码成空串的特殊 token，"在头之前还是之后"光看文本判不出来。因此：

- 命名改成「用户这一轮文本结束、生成脚手架之前」，不再声称「助手角色头之前」；
- 真正的保证不是这个名字，而是**落点 ≤ 本轮真实公共前缀**——由引擎传下去的 `maxPos` 与
  `CheckpointStore.find` 一起守住（各有测例），不写死 1116；
- 「结构上不会有别的边界」这个前提已由启动即跑的分叉点实测覆盖（第一轮/第二轮 1120/1275、公共前缀 1116，
  见第 1 节表格与真机测例）。

这也解释了 P2-1c 为什么只能整段重读：两轮的分叉点几乎贴着上一轮提示的末尾，而循环层状态只能整份存、
整份取，所以只能在「分叉点之前的那个干净边界」上存。

## 2. 设计

### 2.1 检查点存在哪里

存 **`checkpointPos = 提示 token 数 − 助手头长度`** 这一个位置（每轮一份）：

- `助手头长度 = tokenize(带 generation prompt).size − tokenize(不带).size`，由原生新增的
  `tokenizeBoundary()` 给出（只格式化、不建上下文，很便宜）；
- 位置在**读提示的过程中跨过 checkpointPos 时**记录（循环层状态只能前进，读过去就回不去了）：

  1. 把提示按 ≤ `n_batch` 的块读到 checkpointPos；
  2. 调 `llama_state_seq_get_size_ext(ctx, 0, PARTIAL_ONLY)` + `get_data_ext` 存下循环层部分；
  3. 继续读剩下的 token（含助手头），再生成。

### 2.2 恢复的顺序

下一轮拿到本轮提示的 token 序列后：

1. 算 `shared = 与上一轮提示的最长公共前缀`（P2-1c 已有）；
2. 在本缓存键的检查点里挑**位置 ≤ shared 的最新一份**；
3. `llama_state_seq_set_data_ext(ctx, bytes, 0, PARTIAL_ONLY)` 恢复循环层；
4. `llama_memory_seq_rm(memory, 0, cp, -1)` 把注意力层裁到 cp，**必须返回 true**；
5. 从 cp 接着读剩下的 token（不再从 0 读）。

任何一步失败都退回 P2-1c 的整段重读，并给出回退原因（见 2.5）。

### 2.3 只对混合 / 循环模型启用

`llama_model_is_hybrid(model) || llama_model_is_recurrent(model)` 为真才走检查点。纯注意力模型行为完全不变
（仍走 P2-1c 的 KV 裁剪）。

### 2.4 检查点的管理

- 跟着 P2-1c 的缓存键走：换人物 / 换会话 / 换模型 / 卸载 / 停止 / 出错，检查点与缓存一起作废；
- 每个缓存键最多 **3** 份（常量），总占用上限 **256 MB**（常量），超了淘汰最旧的；写入前按
  `get_size_ext` 预检，单份就超上限的不存（记一条日志）；
- 存下来的是一段字节，不持有原生指针，卸载后不会悬空。

### 2.5 回退原因（在 P2-1c 的 0–3 之后接着编，**不复用 4**）

| 码 | 含义 |
|---|---|
| 5 | 这个缓存键下没有位置 ≤ 公共前缀的检查点（第一次、或分叉点比所有检查点都靠前） |
| 6 | 找到检查点但恢复失败（`set_data` 或随后的 `seq_rm` 返回 false），已退回整段重读 |
| 7 | 关闭了检查点开关（对照用） |

### 2.6 统计（在 P2-1c 的 `GenerationStats` 上追加，默认值保持旧行为）

`fromCheckpoint: Boolean`、`checkpointPos: Long`、`checkpointBytes: Long`、`checkpointStoreMillis: Long`、
`checkpointRestoreMillis: Long`。原有的 `reusedPromptTokens` / `readPromptTokens` / `reuseFallbackReason`
语义不变（复用数包含检查点那一段）。

### 2.7 总开关

原生侧 `CHECKPOINTS_ENABLED`（常量）+ 本侧 `LocalModelEngine.checkpointsEnabled`（可注入，给测例与真机对照用）。
关机时行为等于 P2-1c，回退原因记 7。

## 4. 风险与对策

- **恢复错状态 → 答非所问**：生死线是温度 0 的逐字比对（真机、真模型，不能只靠假原生层）。不过就关总开关交付并报统筹。
- **检查点太大/太慢**：真机量一份多大、存一次/取一次多快，按实测调份数与上限。
- **模板换了、落点算法失效**：助手头长度是**量**出来的，不是常数；换模型不会错位。
- **并发**：引擎本来就是 single-flight（`gate` 互斥），检查点只在这一把锁里读写，不新增共享可变状态。

## 8. 真机结论（2026-10-23 早，S2/S3 落地后）

设备 NX809J / SM8850 / Android 16，模型 `Qwen3.5-4B-Q4_K_M.gguf`，线程 8、上下文 8192。
证据：仓库外 `logs\p2-1d-evidence\p2-1d-s5.txt`（逐字比对）、`p2-1d-boundary.txt`（边界解码）。

**能成立的**：

- 单份检查点实测 **52691548 字节（50.2 MB）**，与审按官方配置推算的 50.25 MB 一致；3 份 158074644 字节。
- 存得下、取得到、恢复调用成功（`restoredFrom` = 上一轮的落点）。
- **温度 0 下开/关检查点逐字相同**（生死线守住）：第 2 轮两组正文都是「想静静地看着你。」。

**不成立的，也是这一包的硬结论**：

- 恢复后**不能**直接跳过读取。试过之后生死线当场报警：开检查点时第 2 轮输出「想听你讲个故事。」，
  关着时「想静静地看着你。」。原因就是审预判的那条——`PARTIAL_ONLY` 只存循环层，普通注意力那半边的
  KV 还是上一轮的旧内容，**位置对了、内容不对**。
- 所以当前实现里**恢复只当验证、读取仍整段重读**（`restoredTo` 参数保留但本侧不参与读取决策，
  原生注释写明原因）。也就是说：**只存 `PARTIAL_ONLY` 这条路拿不到提速**。

**要真提速需要什么**（下一包的前提，本节留作交接）：

1. 检查点必须**连注意力 KV 一起存**（`flags = NONE`），单份体积按注意力层数 × 窗口线性增长——
   官方 48 层 / 1 层循环的配置下约为现在的 24 倍量级，必须重新算内存预算与落盘策略；
2. 恢复后仍需 `seq_rm(pos)`，且这次它会真的有事可裁（循环层 rollback ≥ 1 的分支才有意义）；
3. 逐字比对、测速、10 轮内存三件必须在**同一份新实现**上重做一遍。

**本轮已完成的必修项**：1（真机逐 token 解码，边界改名）、3（旧分支作废 + 生命周期）、4（分流顺序）、
5（原因码 0..7 + 读数扩到 10 项）、6（MiB + 先腾后拷）、8（卸载/换模型作废）。必修项 2 的判据已按审实现
（`written == size`、`set_data_ext == size`），必修项 7 的开关默认关已成立（生产代码里无人打开）。
