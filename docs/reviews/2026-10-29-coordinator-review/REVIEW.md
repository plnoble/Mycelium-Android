## 三、问题（按严重程度）

### P1：合并前必须解决

1. **三条线要先整合。** 两两试算，文本冲突不多：
   - A+C：`LocalModelsViewModel.kt`；
   - A+B：`HearthViewModel.kt`；
   - B+C：`HearthViewModel.kt`、`engine.cpp`。

   但有**语义冲突**：大模型加载有两套做法。
   - B 线 `9e87c43` 是「拷进私有缓存再按路径加载」的 wip。它会悄悄拷 7.3 GB，拷到一半被系统杀，后来关掉了；
   - C 线是「保留 fd 直接 mmap」，有 Codex 审核和真机通过。

   **统筹裁定：留 C 线的做法，B 线那套拷贝逻辑整段删掉，不要留着关掉的代码。**
2. **调速做了两套。**
   - P2-5 在 `789c63a` 以后加了 `ThreadTuner`（4/6/8 线程实测）和核数检测（`PhoneCapabilities`、`CoreCountDetectionTest`）；
   - 正在做的按机调优又在 C 线上写了一套：`CpuTopology`、`BenchmarkRunner` 里的 4/6/8 档比较，也改了 `PhoneCapabilities`。

   C 线看不到 P2-5 后来的这些代码，所以是在重复造。**统筹裁定：**
   - 按机调优先停在一个提交上（未完成就写明 wip）；
   - 先把 P2-5 和 C 线整合好；
   - 再在整合分支上接着做按机调优：核数检测和线程实测只留一套，以 P2-5 的为底，按机调优在它上面扩展（按模型保存配置、上下文档位、热状态熔断）。
3. **Codex 审核缺口。** 下面这些包都要补 Codex 全量审，复审最多三轮。未审的包不算交付完成：
   - P2-5 全量审；
   - B 线五个包；
   - 模型测速；
   - 按机调优（做完以后）。

   **原因已查明：** `%LOCALAPPDATA%\OpenAI\Codex\bin\` 下最新的目录（`0354bc6c…`）里只有 `rg.exe`、没有 `codex.exe`；能用的是 `0ab0e7a8…`（codex-cli 0.165）。开发 agent 按「取最新目录」去找，找不到，就记成了「本机没有 codex」。任务书改成「取最新的、含 `codex.exe` 的目录」。
4. **数据库升级路径。** 炉边库从 main 上的 v3，经 v4/v5（人物活性）、v6（复盘）、v7（认知边界）、v8/v9（P2-X），一路升上来；另外预设阵容迁移 v2 会删掉阿远、外婆、老陈（有对话记录的保留），并重置年糕和老K 的文案。用户手机上装着 0.4.0，即将升到 0.5.0 的数据，都会走这条路。所以整合后必须专门验一遍：
   - JVM：用照 0.5.0 真实形状造的库（有人物、有对话、有云端确认、有审计），从 v3 升到最新，**一条不丢**。有对话记录的预设人物保留；用户自己改过的预设人物怎么处理，要写清楚；
   - 真机：先在调试包里用 0.5.0 的版本造数据，再覆盖装整合后的版本，核对人物、对话、记忆、审计都在。
5. **复盘功能的入口已经关了，代码还在。** 它和 P2-3 记忆的范围重叠（「记得的事」）。合并时保持关闭，并在 P2-3 方案里决定：复盘作为 P2-3 的底子，还是由 P2-3 取代。这件事不能拖到合并以后再说。

### P2：合并前最好解决

6. **Windows 门禁数警告的规则比 Linux 窄。** 0.5.0 的 CI 因为一条 `ccache not found` 失败，本机门禁却没拦住（统筹已用 `GGML_CCACHE=OFF` 修了来源，`59e349e`）。`check-all.ps1` 和 `check-all.sh` 判定警告的规则要对齐，并加自测。
