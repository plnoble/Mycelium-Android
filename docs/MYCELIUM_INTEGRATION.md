# 知衍安卓版 × Windows 版：对接说明

2026-09-29 · 用户已批准，v1.1。总计划（唯一依据）在 Windows 仓库：`D:\Agent\Project\OMNIX-Mycelium（知衍）\MYCELIUM-双端总计划-2026-09-29.md`。本文只写安卓版需要知道的部分。

## 0. 名称

- 仓库原叫 `Nivra`（2026-09-29 更名），现在叫 `Mycelium-Android`：
  - App 显示名改为「知衍」；
  - 包名改为 `com.xavierxia.mycelium`。
- **「Nivra」不再用于产品**，只作为旧仓库名留在历史说明里。

## 1. 定位

- **知衍安卓版 = 随身聊天端**。一个 App 里有两个空间：
  - **伴侣空间**：原先规划的 AI 伴侣。本地模型、长期记忆、关系、（后续）语音。
  - **圆桌空间**：和 Windows 版蒸馏出的「圆桌角色」单聊；让多个角色讨论用户的方案；讨论结果可以存档、存为点子。
- **知衍 Windows 版 = 角色工坊**：蒸馏角色、持续投喂、版本确认、点子孵化等重活，都在电脑上做。
- 两个空间在界面上要**明显区分**（颜色、图标），用户任何时候都知道自己在哪个空间。

## 2. 隐私硬要求（每条都要有自动化测试）

三级数据，**只能往里流**：

| 级别 | 内容 | 规则 |
|---|---|---|
| 亲密 | 伴侣聊天、伴侣记忆、关系状态 | 只在手机上加密存储；不联网、不同步；只能用用户自己的密码导出加密备份 |
| 工作 | 圆桌里的问题/方案、讨论记录、点子、背景卡 | 自己设备之间加密同步；只有圆桌空间、且选了云端档位时才发给云端，并留审计记录 |
| 公开派生 | 角色包 | 可以作为云端提示的一部分 |
| 密钥 | API key、设备密钥 | Android Keystore / 加密存储，永不明文同步 |

- **往里流可以**：伴侣可以知道「用户今天和简七讨论了定投」。
- **往外流不行**：伴侣聊天里的内容要存成点子，必须用户手动操作，并先预览要带出去的原文。

技术要求：
1. 伴侣、圆桌各用一个加密数据库（SQLCipher 或自带 SQLite + Keystore 包装的密钥，由 P0-7 探针决定）。
2. **模块依赖隔离**：伴侣模块不得依赖任何联网模块，用架构测试守住（依赖图检查，谁加了这种依赖测试就红）。
3. **唯一出网网关**：
   - 白名单：GitHub 更新检查、用户配置的云端模型、已配对的电脑。
   - 每次出网都写本地审计记录：时间、目标、所属空间、字数、内容，可查看。
4. **类型隔离**：云端提示只能用圆桌的数据类型拼出来，类型层面拿不到伴侣数据；本地模型切换空间时清空上下文和 KV 缓存。
5. 锁屏通知不显示聊天内容；可选指纹锁。
6. 云端服务商优先选有「API 数据不用于训练」明文条款的，设置里标注条款链接。

## 3. 模型路由

| 场景 | 默认 | 可选 |
|---|---|---|
| 伴侣聊天、记忆整理 | 手机本地（Qwen3.5-4B 起步，P0-7 实测 9B） | 不上云端 |
| 角色单聊 | 云端 | 手机本地精简版 / 家里电脑（阶段 5 可选） |
| 多角色讨论 + 总结 | 云端 | 家里电脑 |

每条消息都标明由谁回答：云端 / 家里 / 本机。圆桌有预算上限：每场的请求数和金额，以及月度上限。

## 4. 契约（Windows 版是真源）

- Windows 仓库的 `contract/` 定义三样东西：
  - **角色包格式**：`.mpack`，内含 `manifest.json` 和只读的 `persona.sqlite`；
  - **检索规则**：FTS5 trigram，外加少于 3 个字的查询回退；
  - **回答协议**：系统提示模板、JSON 输出格式、校验与渲染规则，陈述要分「原文依据 / 【推演】」。
- 本仓库把它原样复制到 `contract/`，记下对应的 Windows 仓库提交号，用 `checksums.json` 校验。
- 安卓的实现要通过契约里的全部样例测试（见 `docs/work-packages/P0-8-contract-consumer.md`）。
- 改契约只能先改 Windows 侧、升版本号，再同步过来；本仓库不得单方面修改 `contract/`。
- 手机上的角色是**只读**的：安卓版不编辑角色，只导入、只用；新版本来了，旧讨论继续用旧版本。

## 5. 同步（阶段 4 才做，先了解）

| 方向 | 内容 |
|---|---|
| 电脑→手机 | 角色包（已确认版本）及变化摘要 |
| 手机→电脑 | 讨论存档（用户点了才传）、点子卡、投喂请求（分享文章「喂给某角色」） |
| 不同步 | 伴侣的一切、密钥 |

分三步：
1. 先手动导入角色包文件；
2. 再做局域网扫码配对的加密自动同步，离线时先存着，回家再发；
3. 可选：经 NAS 中转。

## 7. 规格变更（由 P0-9 落实到 `README.md` / `docs/PRODUCT_SPEC.md`）

- 产品名改为「Mycelium（知衍）」，去掉「Nivra」。
- 「multi-agent systems」：伴侣空间仍然不做；**圆桌空间允许**。
- 「cloud」：伴侣空间永不联网；圆桌空间只经网关使用云端模型。
- 「cloud sync」：仍然不做云同步；只做**自己设备之间的局域网同步**。
- web search、MCP、character marketplace、3D/Live2D：仍然不做。
- 原则里增加「Privacy-first（隐私分级、只能往里流）」和「Evidence-first（圆桌回答必须可追溯）」。

## 8. 建议的模块划分（后续工作包据此拆分，第 0 阶段不动）

```
:app         界面外壳、导航、两个空间的入口
:contract    纯 Kotlin/JVM：角色包解析、检索、回答校验（跑契约样例）
:llm         llama.cpp 引擎（可替换接口、流式）

:roundtable  圆桌：角色、讨论编排、总结、点子  —— 可以依赖 :net
:net         唯一出网网关：白名单、审计、云端客户端、同步客户端、更新检查
:storage     加密数据库（每个空间一个）、Keystore
```
