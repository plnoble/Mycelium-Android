# P2-2 炉边：创建自己的人物，用本地模型对话

- 仓库 / 基准：安卓仓库 `main`（P2-1 合并后）→ 分支 `wp/P2-2-hearth-chat`
- 工作目录：由统筹在 `TRACKS.md` 里指定。
- 依赖：P2-1 已合并；P1-6a（「伴侣」改名「炉边」）已合并。
- 预计规模：5–7 个工作日
- 发布：版本号由统筹按合并顺序定。推送、合并、打标签、发布都要用户同意。
- 背景：
  - 2026-10-17 用户决定：在「炉边」里创建属于自己的人物，用本地模型对话。人物性格由用户随意设定，不预设任何关系。
  - 总计划 §4 的隐私硬要求：炉边只用手机本地模型，不联网、不同步，用自己的加密库。

## 目标（用户能得到什么）

- 打开「炉边」，新建一个人物，写好名字、性格、说话方式，就能和它聊天。
- 回答一个字一个字地出来，随时能停。
- 关掉 App 再打开，人物和对话都还在。飞行模式下照样能用。

## 页面

1. **炉边首页**：人物列表（名字、一句话简介、最近一次对话时间）；「新建人物」按钮；没有人物时显示一句说明。
2. **人物编辑**：
   - 名字（必填）；头像用一个字和一种颜色。
   - 性格、说话方式、背景设定：都是自由填写的文字。
   - 和你的关系：可选，自由填写，不给预设选项。
   - 开场白：可选。
   - 用哪个本地模型（从 P2-1 导入的模型里选）、生成参数（温度等，给好默认值）。
   - 可以编辑、复制、删除。删除前确认，对话一起删除。
3. **对话页**：
   - 流式显示回答；「停止」按钮；重新生成最后一条回答。
   - 「新对话」；每个人物有自己的历史对话列表，可以删除单段对话。
   - 每条回答下面标「本机 · <模型名>」。

## 做法

- **提示拼装**：系统提示由人物的各个字段拼成，模板写在代码里，并有单测。
- **上下文**：超出上下文长度时，从最早的轮次开始截掉，人物设定始终保留；截掉时界面给一个不打扰的提示。
- **存储**：炉边用自己的加密库（SQLCipher + Keystore，P0-7 方案），和圆桌的库分开。
- **模块**：`:hearth` 放炉边的数据、提示拼装和对话逻辑，只通过 `:model-api` 调模型。P1-7 写好的架构规则要真正生效：`hearth` 开头的模块不许依赖 `:net`，也不许依赖 HTTP 库。
- **隐私**：不写对话内容日志；锁屏通知不显示内容；炉边不联网，所以没有出网审计记录。

## 不做

- 记忆提取和检索（P2-3）、语音、主动消息。
- 云端模型：炉边不联网。
- 把炉边的内容带到圆桌。
- 人物的导入、导出和分享。

## 2026-10-18 修订（用户决定；和上文冲突的地方以这里为准）

- 分支 `wp/P2-2-hearth-chat` 上已经有 6 个提交（`:hearth` 模块、三个页面、加密库、真机加密测例），在它上面继续做。开工前先把最新的 `main` 并进来；P2-1b 合并后，再用 `scripts/check-all.ps1` 清掉警告。
- 上文「云端模型：炉边不联网」作废。现在的规矩是：炉边人物**默认用本地模型、不联网**，每个人物可以单独改用云端模型；联网搜索开关留给 P2-4。

### 修订内容

1. **每个人物选模型**，三选一：
   - 「默认本地模型」：跟随全局默认。P2-5 做出全局默认之前，先用「我的 → 本地模型」里已登记的第一个。
   - 指定某个本地模型。
   - 指定某个云端模型（P1-7 里已保存的服务和模型）。
   - `:hearth` 只通过 `:model-api` 的 `ChatModel` 调模型，具体实现由 app 注入。`:hearth` 仍然**不许依赖 `:net` 和任何 HTTP 库**，架构测试保留。云端请求走 P1-7 的网关，审计用途新增「炉边聊天」。
2. **云端的隐私提示**：
   - 人物用云端模型时，人物卡片和对话页都标「云端」。
   - 第一次把某个人物切到云端时，弹一次说明：「这个人物的聊天内容（以后还有它对你的记忆）会发给 <服务名>」。用户确认后才生效。
   - 每条回答下面标「本机 · <模型名>」或「云端 · <服务名> <模型名>」。
3. **测试模式和沉浸模式**：对话页顶部一个开关，默认沉浸模式。
   - 沉浸模式：照现在的做法保存对话。P2-3 会在这个模式下加记忆。
   - 测试模式（相当于无痕）：不写库，不留历史，离开对话页就没有了；界面上明显标「测试模式 · 不留记录」；不读也不写这个人物的记忆（P2-3 实现时遵守）。停止和重新生成照常能用。
   - 测试模式下用云端模型时，审计记录只记时间、服务、字数和「炉边 · 测试模式」，**不记正文**。为此给网关请求加一个「不记正文」的选项；其他用途照旧记正文。
4. **预设人物**：第一次打开炉边、而且从没放过预设时，把预设人物放进列表。预设就是普通人物，可以编辑、可以删除；删掉的不再自动加回来。内容见下面的附录。统筹起草，用户可以改。
