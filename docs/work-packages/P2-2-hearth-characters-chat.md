# P2-2 炉边：创建自己的人物，用本地模型对话

- 仓库 / 基准：安卓仓库 `main`（P2-1 合并后）→ 分支 `wp/P2-2-hearth-chat`
- 工作目录：由统筹在 `TRACKS.md` 里指定。
- 依赖：P2-1 已合并；P1-6a（「伴侣」改名「炉边」）已合并。
- 预计规模：5–7 个工作日
- 发布：版本号由统筹按合并顺序定。推送、合并、打标签、发布都要用户同意。
- 背景：
  - 2026-10-17 用户决定：在「炉边」里创建属于自己的人物，用本地模型对话。人物性格由用户随意设定，不预设任何关系。
  - 总计划 §4 的隐私硬要求：炉边只用手机本地模型，不联网、不同步，用自己的加密库。

## 目标（用户能得到什么）

- 打开「炉边」，新建一个人物，写好名字、性格、说话方式，就能和它聊天。
- 回答一个字一个字地出来，随时能停。
- 关掉 App 再打开，人物和对话都还在。飞行模式下照样能用。

## 页面

1. **炉边首页**：人物列表（名字、一句话简介、最近一次对话时间）；「新建人物」按钮；没有人物时显示一句说明。
2. **人物编辑**：
   - 名字（必填）；头像用一个字和一种颜色。
   - 性格、说话方式、背景设定：都是自由填写的文字。
   - 和你的关系：可选，自由填写，不给预设选项。
   - 开场白：可选。
   - 用哪个本地模型（从 P2-1 导入的模型里选）、生成参数（温度等，给好默认值）。
   - 可以编辑、复制、删除。删除前确认，对话一起删除。
3. **对话页**：
   - 流式显示回答；「停止」按钮；重新生成最后一条回答。
   - 「新对话」；每个人物有自己的历史对话列表，可以删除单段对话。
   - 每条回答下面标「本机 · <模型名>」。

## 做法

- **提示拼装**：系统提示由人物的各个字段拼成，模板写在代码里，并有单测。
- **上下文**：超出上下文长度时，从最早的轮次开始截掉，人物设定始终保留；截掉时界面给一个不打扰的提示。
- **存储**：炉边用自己的加密库（SQLCipher + Keystore，P0-7 方案），和圆桌的库分开。
- **模块**：`:hearth` 放炉边的数据、提示拼装和对话逻辑，只通过 `:model-api` 调模型。P1-7 写好的架构规则要真正生效：`hearth` 开头的模块不许依赖 `:net`，也不许依赖 HTTP 库。
- **隐私**：不写对话内容日志；锁屏通知不显示内容；炉边不联网，所以没有出网审计记录。

## 不做

- 记忆提取和检索（P2-3）、语音、主动消息。
- 云端模型：炉边不联网。
- 把炉边的内容带到圆桌。
- 人物的导入、导出和分享。

## 测试

- JVM：
  - 人物的增、删、改、复制；
  - 提示拼装：字段有空有满时的输出；
  - 上下文截断：人物设定一定保留，从最早的轮次开始截；
  - 加密库：库文件里搜不到明文的人物设定和对话；
  - 架构测试：`:hearth` 不依赖 `:net`，也不依赖 HTTP 库。
