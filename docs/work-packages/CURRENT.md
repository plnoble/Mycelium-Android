## 0. 常驻规则

### 0.1 节奏
- **连续干。** 一轮里一项接一项往下做：改代码 → 编译 → 跑测 → 提交 → 下一项。中间不停下来汇报。
- 只有三种情况结束这一轮：
  1. 本文件里能做的都做完了；
  2. 需要用户：用手机、要用户做决定；
  3. 卡住了，一小时内解决不了。
- 等 Codex 复审时不结束这一轮：复审放后台跑，同时做别的项。
- 一个包交付以后，**不等统筹验收**，直接做下一节里依赖已经满足的包。只有依赖还没合并进 main 的才要等。

### 0.2 上下文和汇报
- 写给用户看的汇报控制在 30 行以内。门禁日志、审核报告、长文档写进文件，汇报里只引用结论行。
- 长文件分几次写。读大文件只读需要的部分（grep、按行号范围读）。
- 中文文件一律用 UTF-8（不带 BOM）写，不要用 Get-Content / Out-File 来回转。

### 0.3 质量
- 每一项单独提交，带有判别力的测例：改坏实现，测例必须变红。
- 交付前，在全新 worktree 对已提交的版本跑 `scripts/check-all.ps1`，要求零失败、零警告。用例数以日志里的模块表为准。
- 推送前要用的 `scripts/check-public.ps1 -Full` 和 `-SelfTest` 也要通过。

### 0.4 手机
- 用之前先问用户。
- 正式版 `com.xavierxia.mycelium` 永远不碰。开工前后各只读核对一次：0.1.1 / code 2 / lastUpdateTime 2026-10-10 05:23:04。
- 系统界面上的「安装」、文件选择器选模型，都由用户自己点；经用户同意后才可以由你点。

### 0.5 绝对不做
- 推送、打标签、发布、改 GitHub 设置。
- 合并进 main（由统筹做）。
- 调用要花钱的云端模型（测试一律用本机假服务）。
- 下载模型（本文件明确要求的除外）。
- 改电脑的系统或网络设置，改手机设置。
- 碰 Windows 仓库。
- 提交 APK、keystore、密钥、本机用户名、设备序列号。证据和日志入库前先脱敏。

### 0.6 Codex
- 每个包：方案审和全量审必做；分步审、专项审，额度够就做。
- 程序在 `%LOCALAPPDATA%\OpenAI\Codex\bin\` 下最新的那个哈希子目录里。用法：`codex exec -s read-only -c windows.sandbox=unelevated -C <全新 worktree> -o <报告文件> "<审核要求>"`。
- 额度读数：`%USERPROFILE%\.codex\sessions\<年>\<月>\<日>\rollout-*.jsonl` 最后一条的 `rate_limits`。
  - 5 小时窗口不低于 90%：等重置，先做别的；
  - 每周额度用完：告诉用户，由用户自己重置。
- **复审最多三轮。** 第三轮还不通过，把剩下的分歧逐条列成清单交统筹裁定，不跑第四轮。

### 0.7 交付
- 每个包都写 `docs/reviews/<日期>-<编号>/DELIVERY.md`，内容包括：
  - 做了什么，提交号；
  - 门禁原文；

  - 真机结果和截图；
