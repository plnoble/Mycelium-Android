# P2-8 炉边剧情与多人场景：旁白加几个人物同场

- 仓库 / 基准提交：安卓仓库 `main`（1.0.0 以后）
- 分支：`wp/P2-8-hearth-scenes`
- 工作目录：`D:\Agent\Project\Nivra`
- 依赖：P2-3（记忆）、P2-3b（场景开场、动作排版）已合并。
- 规模：5–8 个工作日，**先做方案**。
- 背景：
  - 2026-10-24 用户定下借鉴同类 App 的「剧情 / 多人场景」玩法，排在 1.0.0 之后。
  - 难点：
    - 本地模型一次只能跑一个，几个人物轮流说话会慢；
    - 每个人物的记忆彼此独立（P2-3），多人场景里谁记住什么，要讲清楚。

## 目标（用户能得到什么）

- 建一个「场景」，选 2–4 个炉边人物进来，再写一段情境，比如「周五晚上，大家在阿远家打牌」。
- 你说一句，场景里合适的人物接话。也可以点名让某个人说，或者点「让旁白推进一下剧情」。
- 每个人物说话保持自己的性格和说话方式。

## 步骤

1. **先写方案（`docs/reviews/<日期>-P2-8/PLAN.md`），过 Codex 方案审以后再写代码。** 方案要回答：
   - **谁来接话**：可选做法有用户点名、轮流、或者先让模型判断「该谁说」。推荐的做法和理由，要量一下本地模型多跑一次判断的代价。
   - **模型**：
     - 每个人物用自己的模型，还是整个场景统一用一个？
     - 本地和云端混用的时候怎么处理？其中任何一个人物用云端，进场景前都要按 P2-2 的规矩确认。
   - **提示怎么拼**：每个人物看到的是「场景情境 + 自己的设定 + 对话历史（带说话人标记）」。要照顾 P2-1d 的检查点，前缀尽量稳定。各人物轮流说话时，检查点按人物分开还是共用，方案里要定。
   - **记忆**：
     - 一个人物在场景里能读到的，只有自己的记忆；
     - 场景结束后，每个人物只记住自己「在场时听到的」；
     - 测试模式照旧不读不写。
   - **旁白**：作为一个特殊的「人物」，没有记忆，只负责描述场面、推动剧情。
2. 按方案实现：场景的建立、编辑、删除，场景对话页，说话人标记，点名，旁白。
3. 场景也有测试模式和沉浸模式，和单人对话一样。

## 范围

- **可以改**：`:hearth`、app 里炉边的页面、炉边加密库（要有版本升级），以及对应测试。
- **不许碰**：`:llm` 引擎内部、`:net` 白名单、圆桌、发布签名和版本号。

## 验收标准（方案审时可以细化）

- [ ] JVM 测试：
  - 谁来接话的逻辑；
  - 每个人物的提示里只有自己的设定和自己的记忆；
  - 场景结束后的记忆归属；
  - 测试模式不读不写；
  - 前缀稳定性。
- [ ] 真机（用户在场）：3 个人物加旁白的场景，聊 10 轮。记录每轮等待时间，人物说话是否像自己。
- [ ] 截图：建场景、场景对话、点名、旁白。
- [ ] 全新 worktree 跑门禁，零失败、零警告。

## 风险

- 本地 4B 模型同时扮几个人，可能串戏、变慢。方案里要实测，如实写，供用户决定场景是否默认用云端。
- 记忆归属一旦出错，就违背「每个人物的记忆彼此独立」。测例必须覆盖。

## 审核

- 方案审、分步审、全量审都要做，复审最多三轮。通过后由统筹合并。
