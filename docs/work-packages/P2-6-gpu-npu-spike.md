# P2-6 GPU / NPU 加速探针：红魔上用 GPU 或 Hexagon 跑本地模型，值不值得做

- 仓库 / 基准提交：安卓仓库 `main`（P2-5 合并后）
- 分支：`spike/P2-6-gpu-npu`（探针代码不合并，只合并结论文件）
- 工作目录：`D:\Agent\Worktrees\Mycelium-Android\spike-P2-6`（用 `git worktree add` 建，不在 `Nivra` 里做）
- 依赖：P2-5 已合并。
- 规模：3–5 个工作日。
- 背景：
  - 用户希望 App 能自动测出本地模型在这台手机上最流畅的运行方式（CPU、GPU、Hexagon NPU 等）。
  - P0-7 只跑通了 CPU；OpenCL（Adreno GPU）当时编不通，原因见 `docs/spikes/P0-7-results.md`。
  - llama.cpp 的 Hexagon 后端需要高通的 Hexagon SDK，要从高通网站下载，而且有许可协议。

## 目标

- 给出一份结论：红魔（SM8850）上，GPU（OpenCL）和 Hexagon NPU 各自能不能编、能不能跑、比 CPU 快多少、稳不稳、发不发烫。
- 结论里写明建议：做或不做；做的话要换哪个 llama.cpp 提交，以及工作量估计。

## 步骤

1. **OpenCL**：先查 P0-7 编不通的原因。在当前固定提交 `5e03bdd…` 上重试；不行就试更新的 llama.cpp 提交，写明用的是哪个提交、为什么换。
2. **Hexagon**：先查清楚需要什么 SDK、多大、什么许可协议，**报给用户、征得同意后才下载**。不同意或者做不到，就如实写进结论。
3. **测量**：方法和 P0-7 一样。用 Qwen3.5-4B Q4_K_M，512 和 2048 token 的提示，生成 256 token，每项 3 次，并记下开始时的温度。和 CPU 6 线程对照。
4. 写 `docs/spikes/P2-6-results.md`。
