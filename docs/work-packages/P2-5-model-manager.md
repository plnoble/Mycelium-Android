# P2-5 「我的 → 模型」：推荐、从 Hugging Face 下载、保存目录、默认模型、自动调速

- 仓库 / 基准提交：安卓仓库 `main`（P2-2 合并后）
- 分支：`wp/P2-5-model-manager`
- 工作目录：`D:\Agent\Project\Nivra`
- 依赖：P2-1、P1-7、P2-2、P2-2b 已合并（下载复用 P2-2b 的网关通用下载）。
- 规模：5–8 个工作日。
- 背景：
  - 2026-10-18 用户决定：在「我的」里集中管理模型。云端部分 P1-7 已经做了（填地址和 key、拉取模型、勾选保存）。本地部分要能：
    - 检测这台手机能跑什么，给出推荐；
    - 从 Hugging Face 下载，也能导入；
    - 自动测出最流畅的运行方式；
    - 设一个默认本地模型；
    - 不同人物用不同模型。
  - 下载的模型要存在用户能看到的目录里，**不用这个 App 也能拿去别处用**。设置里要有「模型保存目录」，默认所有下载都存到那里。
  - 国内直连 Hugging Face 常常很慢或连不上，所以要能切换到镜像。

## 目标（用户能得到什么）

- 打开「我的 → 模型 → 本地」，看到「这台手机推荐：……」，点一下就能下载；下载到自己选的目录，比如 `/sdcard/Models`；下载完会自动校验、自动试跑。
- 把一个模型设为默认，所有用「默认本地模型」的人物都跟着用它；某个人物也可以单独指定另一个。

## 步骤

1. **手机能力检测**：读取内存总量和可用量、芯片型号（`Build.SOC_MODEL`）、CPU 核数、剩余存储空间，据此给出推荐档。阈值按红魔的实测来定，写进交付报告。
2. **推荐目录**：内置一个小的模型目录，每条写明：
   - 模型名、Hugging Face 仓库名、文件名、大小、SHA256、建议内存、许可证。
   - **开工时在 Hugging Face 上逐个核对仓库和文件是否真实存在**，交付报告写明核对日期；不要凭印象写。
   - 至少包含 P0-7 测过的 Qwen3.5-4B 和 9B 的 Q4_K_M。
3. **模型保存目录**：
   - 设置里加「模型保存目录」，用系统目录选择器（`ACTION_OPEN_DOCUMENT_TREE`，持久授权）选一个手机上的公共目录。
   - 第一次下载时还没设的话，先让用户选（建议 `/sdcard/Models` 或「下载/Models」）。
   - 文件按原名存成普通 `.gguf`：不加密、不改名、不放进 App 私有目录，别的 App 也能用。
4. **下载**：
   - 下载源可选「Hugging Face 官方」或「镜像 hf-mirror.com」，也能自己填地址。
   - **走网关**：用途新增「下载模型」。白名单加上官方、镜像，以及它们实际存放文件的下载域名（Hugging Face 的文件下载会重定向到别的域名，比如 `cdn-lfs*.huggingface.co`、`cas-bridge.xethub.hf.co`，以开工时实测为准）。下载本身直接复用 P2-2b 给网关做的通用下载：按流写文件、进度、取消、断点续传、每一跳都重新过白名单的重定向、每次下载一条审计（不记文件内容）。这里只加用途、白名单和前台服务，不另写一套。
   - 显示进度，可以暂停、取消、断点续传；空间不够先拦下；提醒用 Wi-Fi。
   - 退到后台也继续下载，用前台服务加通知显示进度，通知里不放个人内容。
   - 下完按目录里的 SHA256 校验，不符就删掉并说明原因。
5. **导入**：保留 P2-1 的导入方式，原地读取，不复制到保存目录。
6. **试跑**：新下载或新导入的模型，先加载一次、生成固定的 64 个 token，记下加载时间和速度。**试跑通过的模型**，才能设为默认或分给人物。
7. **自动选最快的设置**：先只做 CPU 线程数，例如 2、4、6、8 各跑一次短测，把最快的那个记成这个模型在这台手机上的默认参数。GPU 和 NPU 等 P2-6 探针有结论再加；界面上先只显示「CPU」，不要做出用不了的选项。
8. **默认本地模型**：在本地模型列表里设一个默认。炉边人物的「默认本地模型」跟随它；删掉默认模型时提示改选一个。
9. **每个人物指定模型**：P2-2 已有这个选项，在这里接上「试跑通过的模型」列表。

## 范围

- **可以改**：`:llm` 的模型登记部分（不改引擎内部）、`:net` 的白名单、重定向处理和下载用途、app 里「我的」和设置页，以及对应测试。
- **不许碰**：llama.cpp 的源码和固定提交（P2-6 再说）、圆桌的数据、`contract/`、发布签名、版本号。
10. **把 `:llm` 纳入 lint 门禁**（P2-1b 审核裁定）：
    - `ModelRegistry` 的空间检查不再直接用 `File.usableSpace`，改成可注入的「可分配空间」查询：安卓上用 `StorageManager#getAllocatableBytes`，JVM 测试用假实现。新的下载流程也用同一个查询。
    - `:llm` 的 lint 配置关掉 `ChromeOsAbiSupport`，写明理由「只支持手机的 arm64-v8a」。
    - `scripts/check-all.*` 加上全模块 lint（或在 `:app` 的 lint 里打开 `checkDependencies`），零 error、零 warning。
11. **本地引擎的跨页面协调**（P2-2 方案审第 7 条挪到这里）：
    - 模型管理页、炉边、以后的圆桌本地模式共用同一个本地引擎。加载、生成、卸载要有统一的协调：谁加载的、谁在用，停止和卸载只作用于自己发起的操作；正在生成时不能被别的页面卸载或换模型。
    - 在模型页导入、删除、改默认模型后，回到炉边时，人物用的模型按最新登记解析；所选模型已经失效，就明确提示，不静默换成别的模型。
    - 测试：两个页面交错加载、生成、卸载的 JVM 测试（用假原生层）；真机上在炉边生成时去模型页点卸载，生成要么正常完成，要么明确提示，不能崩溃。

  - 断点续传；

## 风险

- Hugging Face 的下载域名和重定向方式会变，所以白名单要按实测写，并在交付报告里记下实测的重定向链。
- 下大模型（几个 GB）耗流量、耗时间，所以真机测试只下小模型，大模型由用户自己决定什么时候下。
