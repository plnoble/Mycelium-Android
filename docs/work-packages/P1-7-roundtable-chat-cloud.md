# P1-7 圆桌单聊（云端模型）：出网网关、审计记录、密钥、模型列表

- 仓库 / 基准：安卓仓库 `main`（P1-6 合并后）→ 分支 `wp/P1-7-roundtable-chat`
- 依赖：
  - P1-6 已合并；
  - 云端服务商：用户 2026-10-15 已确认，默认用 **DeepSeek 官方接口**。
- 开工后修订（2026-10-17，用户决定）：
  - 云端设置改成「填地址和 key → 拉取可调用的模型 → 多选保存 → 聊天时选用」，不再只填一个模型名。
  - **不要单价、每月上限、费用估算和预算拦截**，用户不设限。已经写了的预算代码删掉。
  - 下面第 2、3、4 条和「测试」一节已按此改过。
- 预计规模：5–7 个工作日
- 发布：做完后发 0.3.0（versionCode 4）。推送、合并、打标签、发布都要用户同意。
- 背景：
  - P1-6 之后，手机能导入角色包、看观点、搜观点，但还不能聊。
  - 总计划 §5.1 定了：角色单聊默认用云端模型，因为要忠实引用、会推演，手机上的小模型容易编。2026-10-15 用户再次确认：圆桌以云端为主，也可以走本地（私密模式）。本包只做云端，本地另开工作包。
  - 总计划 §4 定了隐私硬要求：所有出网请求走唯一网关、本地留审计记录、密钥进系统安全存储、圆桌用加密库。本包把这几条一起落地。

## 目标（用户能得到什么）

- 在人物页点「聊天」，向简七提问。回答按契约的回答协议生成：
  - 每句话标明是「原文依据」还是「【推演】」；
  - 引用号点开能看到原文片段和来源；
  - 包里没有依据的问题，它会明说不知道。
- 在「我的」里填好云端服务的地址和 key，一键拉取它能调用的模型，勾选要保存的（可以多选）；聊天时从保存的模型里选一个。
- 每条回答下面写明「云端 · <服务名> <模型>」。
- 所有发出去的内容，都能在「我的 → 隐私记录」里查到。

## 做法

1. **模块划分**（为隐私架构测试打基础）：
   - `:net`：唯一能联网的模块，HTTP 库只在这里。对外提供「出网网关」。现有的检查更新也改走它，行为不变。
   - `:roundtable`：圆桌的数据、检索调用、提示拼装、回答校验。通过网关接口发请求，不直接依赖 HTTP 库。
   - `:contract`：不变，纯 Kotlin，不联网。
   - 炉边模块（原称「伴侣」）下一阶段才建。现在先把架构测试规则写好：将来名字以 `hearth` 开头的模块，不许依赖 `:net`。
2. **出网网关**：
   - 白名单：GitHub 更新用到的 API 和下载域名、用户配置的云端模型地址。其他地址一律拒绝。
   - 每次请求写一条本地审计记录，内容包括：
     - 时间、目标域名、用途（更新 / 拉取模型列表 / 圆桌聊天）；
     - 发送字数和发送的完整内容，不含密钥和认证请求头；
     - 结果（成功或失败、状态码）；接口返回了 token 用量的话一并记下，只记录，不拦截。
   - 「我的 → 隐私记录」能按时间查看，也能清空。
3. **云端模型设置**（「我的 → 云端模型」）：
   - 可以添加多个云端服务。每个服务填：名称、接口地址、API key。没有单价、上限这类输入框。
   - 新建时地址默认预填 DeepSeek 官方接口。开工时按 DeepSeek 官方文档核对当前地址，交付报告写明核对日期和来源。key 由用户自己在手机上输入。
   - 填好后点「拉取模型」：按 OpenAI 兼容接口调用 `GET {接口地址}/models`（带 key），列出可调用的模型。请求走网关，记审计（不含 key）。
   - 用户勾选要保存的模型，可以多选；之后也能再拉取、增减。拉取失败（地址错、401、超时、返回格式不认识）时给出中文说明，不清掉已保存的模型。
   - 聊天页能从已保存的模型里选一个，记住上次的选择。
   - key 用 Android Keystore 包装后保存（P0-7 已验证）。保存后只显示末 4 位。key 不写日志、不进审计记录、不进崩溃报告。
   - 标注服务商「API 数据是否用于训练」的条款链接（DeepSeek 默认填好；用户自加的服务可以留空）。查不到明文条款，就写「未找到明文条款」。
4. **聊天**：
   - 流程：提问 → 用 `:contract` 在包里检索（按契约）→ 按 `answer/system-prompt.zh.txt` 和 `mode-rules.zh.json` 拼提示 → 经网关调用 → 按 `output.schema.json` 和 `VALIDATION.md` 校验 → 渲染。
   - 调用模型这一步放在一个「回答模型」接口后面，本包只实现云端这一种。以后的本地私密模式接同一个接口，检索、拼提示、校验、渲染、存库都不用改。本地模型引擎由 P2-1 做，接口最后统一到 P2-1 的纯 Kotlin 模块 `:model-api`：哪个包后合并，就由哪个包负责对齐。
   - 校验不过时：显示「这次回答不合格，没有显示」，并能展开看原因。不合格的内容不能当回答显示。消费端不得依赖「修复式解析」（`VALIDATION.md` 第 3 条）。
   - 回答模式：契约的三种模式都支持，默认「允许推演」（`thought_inference`），可以切到「只说有原文依据的」（`strict_evidence`）。
   - 引用号点开显示依据卡：片段、来源标题、日期。
   - 对话存进圆桌的加密库（SQLCipher + Keystore）。每段对话记住它用的是哪个角色包版本；人物导入新版本后，旧对话继续用旧版本。
   - 对话可以删除。
5. **不做**：多人圆桌（阶段 3）、背景卡、炉边、本地模型单聊（私密模式，另开工作包）、流式输出（可选，不要求）。

## 测试

- JVM：
  - 契约 `answer/vectors/*.json` 全部符合期望，并接到真实的渲染代码上；
  - 用假的云端服务（MockWebServer）覆盖：正常回答、不合格回答、超时、401、429；
  - 拉取模型列表（MockWebServer）：正常列表、空列表、401、超时、返回格式不认识；多选保存、再次拉取后增减、拉取失败时已保存的模型不丢；
  - 网关：白名单外的地址被拒；每次请求（含拉取模型列表）都有审计记录；审计记录里没有 key；
  - 没有任何预算或单价拦截：连续发送不会因为「超上限」被拒；
  - 架构测试：只有 `:net` 依赖 HTTP 库，`:roundtable` 和 `:contract` 不依赖；炉边规则已写好；
  - 加密库：在库文件里搜不到明文对话内容。
- 真机：
  - 用电脑上跑的假云端服务，经 `adb reverse` 转到手机的 `127.0.0.1`。只在 debug 包里允许这个明文地址。
  - 在「我的 → 云端模型」里对假服务拉取模型、勾选两个保存，截图。
  - 用样例人物「陆川」问 3 个问题：一个有依据的、一个要推演的、一个包里没有的；中途在聊天页换一次模型。截图规则同 P1-6。
