# P1-7 圆桌单聊（云端模型）：出网网关、审计记录、密钥、预算

- 仓库 / 基准：安卓仓库 `main`（P1-6 合并后）→ 分支 `wp/P1-7-roundtable-chat`
- 依赖：
  - P1-6 已合并；
  - 云端服务商：用户 2026-10-15 已确认，用 **DeepSeek 官方接口**。
- 预计规模：5–7 个工作日
- 发布：做完后发 0.3.0（versionCode 4）。推送、合并、打标签、发布都要用户同意。
- 背景：
  - P1-6 之后，手机能导入角色包、看观点、搜观点，但还不能聊。
  - 总计划 §5.1 定了：角色单聊默认用云端模型，因为要忠实引用、会推演，手机上的小模型容易编。2026-10-15 用户再次确认：圆桌以云端为主，也可以走本地（私密模式）。本包只做云端，本地另开工作包。
  - 总计划 §4 定了隐私硬要求：所有出网请求走唯一网关、本地留审计记录、密钥进系统安全存储、圆桌用加密库。本包把这几条一起落地。

## 目标（用户能得到什么）

- 在人物页点「聊天」，向简七提问。回答按契约的回答协议生成：
  - 每句话标明是「原文依据」还是「【推演】」；
  - 引用号点开能看到原文片段和来源；
  - 包里没有依据的问题，它会明说不知道。
- 每条回答下面写明「云端 · <服务商> <模型>」。
- 所有发出去的内容，都能在「我的 → 隐私记录」里查到。

## 做法

1. **模块划分**（为隐私架构测试打基础）：
   - `:net`：唯一能联网的模块，HTTP 库只在这里。对外提供「出网网关」。现有的检查更新也改走它，行为不变。
   - `:roundtable`：圆桌的数据、检索调用、提示拼装、回答校验。通过网关接口发请求，不直接依赖 HTTP 库。
   - `:contract`：不变，纯 Kotlin，不联网。
   - 伴侣模块下一阶段才建。现在先把架构测试规则写好：将来名字以 `companion` 开头的模块，不许依赖 `:net`。
2. **出网网关**：
   - 白名单：GitHub 更新用到的 API 和下载域名、用户配置的云端模型地址。其他地址一律拒绝。
   - 每次请求写一条本地审计记录，内容包括：
     - 时间、目标域名、用途（更新 / 圆桌聊天）；
     - 发送字数和发送的完整内容，不含密钥和认证请求头；
     - 结果（成功或失败、状态码）、本次费用估算。
   - 「我的 → 隐私记录」能按时间查看，也能清空。
3. **云端模型设置**（「我的 → 云端模型」）：
   - 可填：接口地址、模型名、API key、输入和输出单价（美元 / 百万 token）、每月上限（美元，默认 5）。
   - 默认填好 DeepSeek 官方接口的地址和模型。开工时按 DeepSeek 官方文档核对当前的接口地址、模型名和单价（总计划记过旧模型下线），交付报告写明核对日期和来源。key 由用户自己在手机上输入。
   - key 用 Android Keystore 包装后保存（P0-7 已验证）。保存后只显示末 4 位。key 不写日志、不进审计记录、不进崩溃报告。
   - 标注服务商「API 数据是否用于训练」的条款链接。查不到明文条款，就写「未找到明文条款」。
4. **聊天**：
   - 流程：提问 → 用 `:contract` 在包里检索（按契约）→ 按 `answer/system-prompt.zh.txt` 和 `mode-rules.zh.json` 拼提示 → 经网关调用 → 按 `output.schema.json` 和 `VALIDATION.md` 校验 → 渲染。
   - 调用模型这一步放在一个「回答模型」接口后面，本包只实现云端这一种。以后的本地私密模式接同一个接口，检索、拼提示、校验、渲染、存库都不用改。
   - 校验不过时：显示「这次回答不合格，没有显示」，并能展开看原因。不合格的内容不能当回答显示。消费端不得依赖「修复式解析」（`VALIDATION.md` 第 3 条）。
   - 回答模式：契约的三种模式都支持，默认「允许推演」（`thought_inference`），可以切到「只说有原文依据的」（`strict_evidence`）。
   - 引用号点开显示依据卡：片段、来源标题、日期。
   - 发送前显示本次费用估算。本月累计会超过上限时不发送，提示用户去「我的」调上限。
   - 对话存进圆桌的加密库（SQLCipher + Keystore）。每段对话记住它用的是哪个角色包版本；人物导入新版本后，旧对话继续用旧版本。
   - 对话可以删除。
5. **不做**：多人圆桌（阶段 3）、背景卡、伴侣、本地模型单聊（私密模式，另开工作包）、流式输出（可选，不要求）。

## 测试

- JVM：
  - 契约 `answer/vectors/*.json` 全部符合期望，并接到真实的渲染代码上；
  - 用假的云端服务（MockWebServer）覆盖：正常回答、不合格回答、超时、401、429；
  - 网关：白名单外的地址被拒；每次请求都有审计记录；审计记录里没有 key；
  - 预算：超上限时不发请求；
  - 架构测试：只有 `:net` 依赖 HTTP 库，`:roundtable` 和 `:contract` 不依赖；伴侣规则已写好；
  - 加密库：在库文件里搜不到明文对话内容。
- 真机：
  - 用电脑上跑的假云端服务，经 `adb reverse` 转到手机的 `127.0.0.1`。只在 debug 包里允许这个明文地址。
  - 用样例人物「陆川」问 3 个问题：一个有依据的、一个要推演的、一个包里没有的。截图规则同 P1-6。

## 不许做

- **不许用真实 key 发任何请求**。开发和走查全部用假服务。真实调用由用户自己在手机上填 key 后发起。
- 不许把 key 写进代码、配置、日志、测试、截图。
- 不改 `contract/` 里的文件，有问题报统筹。
- 不碰发布签名配置和 `release.yml`。
