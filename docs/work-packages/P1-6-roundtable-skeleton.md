# P1-6 圆桌空间骨架：页面、导入角色包、浏览和搜索观点

- 仓库 / 基准：安卓仓库 `main`（P0-8 合并后）→ 分支 `wp/P1-6-roundtable-skeleton`
- 依赖：P0-8 契约消费方已合并（`:contract` 能读包、能检索）。
- 预计规模：4–5 个工作日
- 发布：做完后发 0.2.0（versionCode 3）。推送、合并、打标签、发布都要用户同意。
- 背景：
  - 用户现在打开手机上的知衍，只有一屏说明文字和「检查更新」按钮，没有任何页面。
  - 电脑端 P1-1 会导出 `.mpack` 角色包。本包让手机能导入它，能看人物、看观点、搜观点。
  - 全程不新增联网（只保留原有的检查更新），不用模型，不花钱。聊天在下一个包 P1-7 做。

## 目标（用户能得到什么）

打开知衍，底部有三个入口：圆桌 / 伴侣 / 我的。在圆桌里点「导入角色包」，选电脑上导出的文件，简七就出现在列表里。点进去能按主题看观点，能看每条观点的原文依据，能按关键词搜。

## 页面

1. **底部导航**：圆桌 / 伴侣 / 我的。圆桌和伴侣用明显不同的主色和图标，任何时候都知道自己在哪个空间（总计划 §3）。
2. **圆桌首页**：
   - 已导入的人物列表：名字、版本标签、发布日期、观点数。
   - 「导入角色包」按钮：用系统文件选择器（`ACTION_OPEN_DOCUMENT`，不申请存储权限）。`.mpack` 没有标准 MIME 类型，要确保选择器里能看到并选中它。
   - 没有人物时显示一句说明：「在电脑版知衍的角色页导出角色包，传到手机后在这里导入。」
3. **导入**：
   - 先完整校验，再保存。校验项：zip 条目和顺序、manifest 结构、`pack_format` / `pack_version`、`contract_version` 是否兼容、重算 `logical_sha256` 与 manifest 一致。
   - 任何一项不过：不保存任何东西，提示里写明哪一项没过。
   - 校验通过后复制进应用私有目录，不放公共存储。
   - 同一人物、同一版本再导入：提示「已经导入过」，不重复保存。
   - 同一人物的新版本：保存为新版本，列表默认显示最新版本，并提示「简七更新：新增 N 条观点、移除 M 条」（按观点 ID 比较）。旧版本保留，可以在「我的」里删。
4. **人物页**：顶部是名字、版本、发布日期、数据截至日期，以及观点、主题、来源数。下面三个分页：
   - **主题**：按包里的主题顺序列出；点进去看这个主题下的观点。
   - **观点**：全部观点列表。简七现在约有 550 条观点、140 个主题，滚动要流畅。
   - **搜索**：输入关键词，按契约 `retrieval/SPEC.md` 检索，结果和顺序与契约一致。显示命中片段和来源标题、日期。2 个字的短查询显示 SPEC 里的提示。
5. **观点详情**：
   - 观点原文、类型、所属主题；
   - 原文依据片段，逐条列出，带来源标题、平台、发布日期；
   - 与其他观点的关系（按包里的 `relationships`）。
6. **伴侣**：只放一页说明：「伴侣空间在下一阶段开发：只用手机上的模型，不联网。」不做功能。
7. **我的**：
   - 版本号和「检查更新」：从原首页挪过来，功能不变；
   - 已导入的角色包列表：人物、版本、导入时间、占用空间；可以删除，删除前确认。

## 技术要求

- 读包用 P0-7 定的 SQLCipher 库。系统自带的 SQLite 没有 FTS5，检索跑不了。角色包本身是公开派生数据，不要求加密，以只读方式打开。
- 不新增任何联网代码。现有的检查更新保持原样。
- 包里的文字（观点、依据片段）只在本机显示，不写日志。
- 新增的界面文字一律中文。
- **debug 包要能和用户手机上的正式版共存**：debug 构建加 `applicationIdSuffix = ".debug"`，应用名显示「知衍（调试）」。真机走查只装 debug 包，**不卸载、不覆盖用户装的正式版**。

## 测试

- JVM：
  - 导入校验：合法的样例包通过。下面几种各自被拒，而且被拒后私有目录里没有留下任何文件：改一个字节、缺条目、条目顺序错、`pack_format` 不对、`contract_version` 不兼容。
  - P0-8 审核留下的三条（见 `docs/reviews/2026-10-15-P0-8/REVIEW-r1.md` 建议 1、`REVIEW.md` 建议 1），本包一起做：截断的 `.mpack`、`persona.sqlite` 不是数据库，都要以 `PackRejected` 拒绝，界面给出说明，不能崩；zip 里的目录条目也算多出的条目；单个条目设大小上限，超过就拒绝。
  - 重复导入同一版本能被识别。
  - 新版本导入后，「新增 N、移除 M」算得对。为此造两个版本的合成包。
  - 删除版本后，文件和记录都清掉。
- 真机 instrumented test：在手机上用选定的 SQLCipher 库打开契约样例包，跑完 `retrieval/vectors.json`，结果和顺序全部一致。P0-8 里这一项是可选的，这里改成必做。
- 原有的 `:app:assembleDebug :app:testDebugUnitTest :app:lintDebug` 和 `:contract:test` 仍然通过。

## 真机走查

- 用契约样例包（虚构人物「陆川」）走一遍：
  1. 导入，包括系统文件选择器；
  2. 看列表；
  3. 进人物页，看三个分页；
  4. 看观点详情；
  5. 搜一个 2 字的词和一个 3 字以上的词；
  6. 再导入同一个包，看到「已经导入过」；
  7. 在「我的」里删除。
- **不要用真实人物的包走查**。真实人物包里有真实文章片段，不能进截图。真实的简七包由统筹导出，用户自己在手机上看。
- 手机截图规则：
  - 只在知衍（调试）处于前台时用 `adb exec-out screencap` 截；
  - 截图裁掉顶部状态栏，通知图标和内容可能在里面；
  - 存图前逐张看一遍，出现任何本应用以外的内容就删掉重截；
  - 截图放 Windows 仓库的 `.omx/development/reviews/<日期>-android-P1-6/`，**不进安卓仓库**（安卓仓库是公开的）。
- 只操作知衍（调试）这一个应用，不碰手机上的其他应用和系统设置。
