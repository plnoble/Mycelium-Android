# P1-8 圆桌本地私密模式：用手机上的模型和角色单聊

- 仓库 / 基准提交：安卓仓库 `main`（P1-7 合并后）
- 分支：`wp/P1-8-roundtable-local`
- 工作目录：`D:\Agent\Project\Nivra`（A-圆桌线）
- 依赖：P1-7、P2-1 已合并。
- 规模：2–4 个工作日。
- 背景：
  - 总计划 §5.1 和 v1.3：圆桌以云端为主，也可以走本地（私密模式）。P1-7 已经把「回答模型」统一到 `:model-api` 的 `ChatModel`，P2-1 的本地引擎 `LocalModelEngine` 也实现了这个接口，所以这一包主要是把两头接起来。
  - 回答协议要求模型整段输出合规 JSON，小模型更容易不合格；提示里带检索到的原文，长度通常在 1000 token 以上。P0-7 和 P2-1 的实测：4B 用 6 线程，读提示约每秒 12 个 token，生成约每秒 8–12 个。所以本地一问一答可能要等一两分钟。

## 目标（用户能得到什么）

- 圆桌聊天页的「选择模型」里，除了云端模型，还能选「本机」的模型（P2-1 导入过的）。
- 选了本机模型时，整段问答完全不联网：飞行模式下也能用，隐私记录里不多出任何一条。
- 每条回答下面标「本机 · <模型名>」。等待期间能看到进度，能随时停止。

## 步骤

1. 模型选单把本地模型和云端模型分组列出；记住上次的选择。还没导入本地模型时，本地那组给一句说明，指向「我的 → 本地模型」。
2. 选了本机模型时：先加载模型（显示加载中，能取消），再用同一套检索、拼提示、校验、渲染流程回答。只换 `ChatModel` 的实现，不另写一套聊天逻辑。
3. 生成过程中，界面不显示半截 JSON，只显示进度（已等待时间、已生成多少字）和「停止」按钮。停止后这一轮不算回答，也不存进对话。
4. 回答校验不合格时，照 P1-7 的做法显示「这次回答不合格，没有显示」，可以展开看原因。
5. 本机模式下不能碰网关：既不发请求，也不写审计记录。

## 风险

- 4B 模型回答不合格的比例可能很高。这不算本包失败，但要如实记录，供用户决定本地模式值不值得用、要不要换 9B。
- 本地模型和炉边共用同一个引擎（一个进程里只有一个模型）。圆桌和炉边来回切换时，后用的那边要重新加载；不许两边同时生成。
