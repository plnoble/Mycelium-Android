## 目标（用户能得到什么）

- 在「我的 → 本地模型」里，用系统文件选择器导入手机上已有的模型文件（`.gguf`），看到名字、大小和校验值。
- 选一个本地模型，能流式生成文字，能随时停止。

## 做法

1. **模块**：
   - `:model-api`：纯 Kotlin，不联网，不含原生库。定义 `ChatModel`（输入消息列表和生成参数，流式输出文字，可以取消）、`ChatMessage`（system / user / assistant）、`ModelInfo`。本地和云端都实现这个接口。P1-7 的「回答模型」接口最后统一到这里，哪个包后合并就由哪个包对齐。
   - `:llm`：Android 库，含 llama.cpp 和 JNI，实现 `ChatModel`。不许依赖 `:net`，也不许依赖任何 HTTP 库。
2. **引擎**：
   - 加载 GGUF：默认上下文 8192、6 线程、CPU。同一时间只加载一个模型。
   - 用模型文件自带的聊天模板拼消息，不手写某一家的格式。
   - 流式回调；点「停止」后 1 秒内停下；卸载后释放内存。
   - 加载和生成都在后台线程，界面不卡。
   - 模型输出思考段（如 `<think>…</think>`）时，默认不当正文显示。交付报告写明怎么处理的。
3. **本地模型管理**（「我的 → 本地模型」）：
   - 用系统文件选择器（`ACTION_OPEN_DOCUMENT`）导入，不申请存储权限，不在 App 里下载模型。
   - 导入时算一次 SHA256（显示进度），记下文件名、大小、校验值；同一个文件不重复登记。
   - 优先不复制：拿持久授权，用文件描述符读取。做不到再复制进应用私有目录，复制前提示要占多少空间。交付报告写明最终用的哪种，以及实测加载时间。
   - 可设线程数（默认 6）和上下文长度（默认 8192）。
   - 移除只删 App 里的登记（和复制件），**绝不删用户的原文件**。
   - 「我的」里的模型页分「本地」和「云端」两组。云端那组由 P1-7 做；两包都合并后，在同一页显示。

## 测试

- JVM：
  - `:model-api` 用假模型测流式和取消；
  - 模型登记：导入、去重、移除，移除后原文件还在；
  - 架构测试：`:llm` 和 `:model-api` 不依赖 `:net`，也不依赖任何 HTTP 库。
- 真机（instrumented test，红魔）：
  - 用手机上已有的 Qwen3.5-4B-Q4_K_M。用户的原文件不许改动；测试需要的话，可以临时复制到测试应用目录，测完删掉。
  - 加载 → 生成 64 个 token → 流式回调按顺序到达 → 生成途中停止，1 秒内停下 → 卸载后内存回落。
  - 记下生成速度，和 P0-7 的结果对照。
