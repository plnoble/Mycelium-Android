# P2-3b 炉边体验小件：多套场景开场、图片头像、动作排版、人物卡导出导入

- 仓库 / 基准提交：安卓仓库 `main`（P2-1d 合并、0.5.0 发布以后）
- 分支：`wp/P2-3b-hearth-touches`
- 工作目录：`D:\Agent\Project\Nivra`
- 依赖：P2-2 已合并。和 P2-1d 都改炉边的提示拼法，所以排在 P2-1d 之后。
- 规模：3–5 个工作日。
- 背景：
  - 2026-10-24 用户看了同类 App（字节的「猫箱」这一类 AI 角色聊天），定下借鉴几样和炉边「本地、私密、人物自己写」不冲突的东西。社区广场、排行推荐、充值会员这些不借鉴。
  - 现在已经有的：
    - 每个人物有一条开场白（`greeting`）。新对话开头会显示它，提示里也写着「你的开场白是：……」（`hearth/.../Prompt.kt`）。
    - 头像只能填一个字（`avatarChar`）。
    - 预设人物的开场白里已经用 `*从纸箱里探出头*` 这种动作写法，但界面上没有区分显示。
    - 人物只能在手机上手写，没法分享。

## 目标（用户能得到什么）

- **场景和开场**：
  - 一个人物可以有几套「场景 + 开场白」，比如「下班后在楼下烧烤摊」「凌晨两点电话里」；
  - 开新对话时挑一套，人物先开口，场景就定下来了。
- **图片头像**：人物可以用一张自己选的图做头像。
- **动作排版**：回答里 `*笑了笑*` 这种动作和旁白，显示成斜体、浅一点的颜色，和说的话区分开。
- **人物卡**：
  - 能把一个人物导出成一个文件，发给朋友，对方导入就能用；
  - 也能导入网上常见的通用角色卡（JSON 格式）。

## 步骤

1. **多套场景和开场**
   - 每个人物最多 5 套，每套包括：
     - 标题，比如「烧烤摊」；
     - 场景说明：写给模型看的情境，几句话；
     - 开场白：人物说的第一句话，可以带 `*动作*`。
   - 现有的 `greeting` 自动迁移成第一套（标题「默认」，场景说明为空）。数据库要有版本升级，老库平滑升级，配测例。
   - 开新对话时：
     - 只有一套，直接用；
     - 有多套，让用户挑，外加一个「随便来一个」。
   - 选中的那一套**跟着这段对话存下来**：
     - 场景说明进系统提示；
     - 开场白作为人物的第一条消息，既显示出来，也作为第一轮「助手」消息进入对话历史。这样模型接得上，以后打开这段对话时也一样。
   - **提示的拼法要照顾 P2-1d 的检查点**：场景说明在一段对话里固定不变，放在系统提示里；开场白放在历史的最前面。同一段对话每一轮的前缀都必须保持不变。
   - 预设人物（阿远、年糕、老K、外婆、老陈）各补 1–2 套场景，你先起草，交付时列出原文给统筹和用户看。
2. **图片头像**
   - 用系统的照片选择器（Android Photo Picker，不需要存储权限）选一张图。
   - 居中裁成正方形，缩到 256×256，存在 App 私有目录（`files/`，不是缓存目录）。
   - 删除人物时，头像文件一起删。
   - 没有图片时，照旧显示那一个字。
   - 头像只在本机显示，不发给云端模型。
3. **动作和旁白排版**
   - 只认成对的 `*...*`，显示成斜体加次要颜色。不成对的星号原样显示。
   - 流式输出时，开头的 `*` 还没等到收尾的 `*`，就先按普通文字显示，等成对了再排版，不要闪来闪去。
   - 只改显示，存的文字和复制出来的文字都保持原样。
   - 人物的回答、开场白、你自己发的话都适用。
4. **人物卡导出**
   - 格式：一个 UTF-8 JSON 文件，扩展名 `.mycelium-character.json`。内容：
     - `format`（例如 `mycelium-character`）、`version: 1`；
     - 名字、单字头像；
     - 图片头像：可选，256 像素的 PNG，base64，不超过 200 KB；
     - 性格、说话方式、背景、和你的关系；
     - 场景和开场（全部几套）；
     - 温度、最长回答、颜色。
   - **不导出**：
     - 模型选择（本地模型和云端服务在别人手机上没有意义）；
     - 云端确认记录；
     - 记忆；
     - 对话；
     - 内部 ID。
   - 存文件用系统的「新建文档」（SAF）。也可以「分享」：系统分享面板加 FileProvider，由用户自己选发给谁。
5. **人物卡导入**
   - 用系统的「打开文档」选文件。导入前要校验：
     - 文件不超过 1 MB；
     - 必填字段齐全；
     - 文字字段有长度上限；
     - 认不得的版本号或格式，直接拒绝，用人话说明原因。
   - **先预览再保存**：把名字、头像和全部设定文字展示给用户看，确认后才存。设定文字会原样进提示，用户要看得到里面写了什么。
   - 导入的人物：
     - 生成新 ID；
     - 模型设成默认本地模型；
     - 云端关着；
     - 标记「导入」。
   - 也要能导入通用角色卡（社区常见的 `chara_card_v2` JSON，只做 JSON，不做嵌在 PNG 里的那种）。字段对应：
     - `name` → 名字；
     - `description` 和 `personality` → 性格、背景；
     - `scenario` → 场景说明；
     - `first_mes` → 开场白；
     - `alternate_greetings` → 另外几套开场，最多凑够 5 套；
     - `mes_example` → 说话方式。

     认不得的字段忽略，对应关系写进交付。
6. **安全兜底对所有人物生效**
   - 「察觉对方有伤害自己的念头时，建议联系身边的人或求助热线」这句，现在写在预设里。改成由 App 在拼提示时统一加上，**所有人物**都有，包括自己写的和导入的。它不存进人物卡，用户也删不掉。
   - 预设里原来那句，去重，不要重复两遍。

## 范围

- **可以改**：
  - `:hearth`（人物、存储、提示）；
  - app 里炉边的页面；
  - 炉边加密库的表结构，要有版本升级；
  - 清单（FileProvider 路径）；
  - 以及对应的测试。
- **不许碰**：
  - `:llm` 引擎内部，包括 P2-1d 的检查点；
  - 圆桌；
  - `:net`；
  - `contract/`；
  - 发布签名和版本号。

## 验收标准

- [ ] JVM 测试：
  - 老库升级：`greeting` 变成第一套场景，内容不丢；
  - 选中的场景跟着对话存，重新打开同一段对话，场景和开场白都还在；
  - 提示拼法：同一段对话连续几轮，前缀逐字不变（场景说明和开场白不随轮次变化）；
  - 动作排版：成对、不成对、嵌套、流式到一半的各种情况；

    - 导出再导入，内容一致（模型、记忆、对话不带）；

## 风险

- 导入的设定文字可能写着奇怪的指令，比如让人物套你的个人信息。所以导入前必须完整预览；安全兜底由 App 统一加，导入的内容去不掉它。
- 场景说明如果每轮都变，会让 P2-1d 的检查点失效、每轮整段重读。所以场景必须在一段对话里固定。

## 审核

- 方案审和全量审必做，复审最多三轮。真机截图交统筹看。通过后由统筹合并进本地 `main`。
