# P2-7 离线语音：说话输入，回答朗读

- 仓库 / 基准提交：安卓仓库 `main`（1.0.0 前后，P2-3 合并以后）
- 分支：`wp/P2-7-offline-voice`
- 工作目录：`D:\Agent\Project\Nivra`
- 依赖：P2-3 已合并。
- 规模：3–4 个工作日。
- 背景：
  - 2026-10-24 用户定下借鉴同类 App 的语音功能，排在 1.0.0 前后。
  - 炉边的原则是「聊的东西不出手机」，所以语音也要**离线**：识别和朗读都用手机自带的离线能力，不悄悄发到云端。

## 目标（用户能得到什么）

- 在炉边对话页按住（或者点一下）麦克风说话，说完自动变成文字，可以先改再发，也可以直接发。
- 人物的回答可以朗读出来：每条消息上有一个「朗读」按钮；也可以给某个人物打开「自动朗读」。
- 不同人物可以调成不同的声音（音调、语速）。

## 步骤

1. **说话输入**
   - Android 12（API 31）以上，用 `SpeechRecognizer.createOnDeviceSpeechRecognizer`；先用 `isOnDeviceRecognitionAvailable` 判断这台手机有没有离线识别。
   - 没有离线识别：界面说清楚「这台手机没有离线语音识别」，麦克风按钮置灰。**不要悄悄退回联网识别。**
   - 第一次点麦克风才申请录音权限（`RECORD_AUDIO`），先说明用途。用户拒了，麦克风照样置灰，其他功能不受影响。
   - 识别出的文字先放进输入框，用户确认或修改后再发。设置里可以改成「说完直接发」。
   - 中文为主，跟随系统语言。
2. **回答朗读**
   - 用系统的 `TextToSpeech`，优先选离线声音（`Voice.isNetworkConnectionRequired == false`）。只有联网声音时，说明清楚，并且默认不用。
   - 朗读时跳过 `*动作*` 那部分（P2-3b 的排版规则），只读说的话。
   - 每条消息有「朗读 / 停止」按钮。每个人物有「自动朗读」开关，默认关。
   - 每个人物的声音参数（音调、语速）存在人物设定里，人物卡导出时一起带上（P2-3b 的格式加字段，版本号 +1，旧卡照样能导入）。
3. **和生成配合**
   - 流式回答时，自动朗读要等一句话完整了再读，不要一个字一个字地读。
   - 用户开口说话时，停掉正在朗读的内容。
   - 停止生成时，朗读也停。
4. **隐私**
   - 录音不存文件，识别完就丢。
   - 测试模式（无痕）下同样不留任何录音和识别记录。

## 范围

- **可以改**：
  - app 里炉边的页面和设置；
  - `:hearth` 的人物设定（声音参数）和人物卡格式；
  - 清单（录音权限）；
  - 以及对应测试。
- **不许碰**：
  - `:llm` 引擎；
  - `:net`；
  - 圆桌；
  - 发布签名和版本号。

## 验收标准

- [ ] JVM 测试：
  - 朗读文本的处理：跳过动作、按句切分；
  - 流式时等整句；
  - 开口时停读、停止生成时停读；
  - 声音参数存取，以及人物卡新旧版本互导；
  - 没有离线识别或权限被拒时，界面状态正确。
- [ ] 真机（红魔，用户在场）：
  - 离线状态（关掉 Wi-Fi 和数据）下说一句话，识别成文字；
  - 朗读一条带 `*动作*` 的回答，动作不读；
  - 两个人物调成不同的声音；
  - 拒绝录音权限，再重新允许。

## 风险

- 不同手机的离线识别、离线声音差别很大。红魔以外的表现，交付时如实写「未验证」。
- 系统朗读的声音可能比较机械。以后如果要更自然的声音，要用本地语音合成模型，另开工作包。
