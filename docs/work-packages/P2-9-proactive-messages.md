# P2-9 人物主动发消息（可关，默认关）

- 仓库 / 基准提交：安卓仓库 `main`（1.0.0 以后）
- 分支：`wp/P2-9-proactive-messages`
- 工作目录：`D:\Agent\Project\Nivra`
- 依赖：P2-3（记忆）已合并。
- 规模：3–5 个工作日。
- 背景：
  - 2026-10-24 用户定下借鉴同类 App 的「人物主动发消息」，排在 1.0.0 之后。
  - 原则：
    - **默认关**，按人物单独打开；
    - 不打扰：有安静时段、有频率上限；
    - 不偷跑：手机没在充电时，不在后台跑大模型。

## 目标（用户能得到什么）

- 给某个人物打开「主动找我」后，它会在你设定的时间段里，偶尔主动发来一句。比如外婆早上问一句「吃早饭没」，阿远在你说过要面试的那天问一句「面得怎么样」。
- 点通知直接进到那段对话，可以接着聊。

## 步骤

1. **设置**（每个人物单独设）：
   - 开关，默认关；
   - 时间段，例如 8:00–21:00；
   - 频率：最多每天一次、每周几次；
   - 锁屏通知显不显示内容：默认不显示，只写「阿远给你发了一条消息」。
2. **消息怎么来**（方案里定，过 Codex 方案审）：
   - 推荐做法：手机**在充电、空闲、温度正常**时（WorkManager 的约束），用这个人物的模型提前生成一句，存起来，到时间再发通知。
   - 生成时参考人物设定，以及它记得的事（P2-3，只在沉浸模式下的记忆）。比如记忆里有「下周三面试」，就在那天之后问一句。
   - 生成失败或者条件不满足，就这次不发，不要硬发，也不要补发一堆。
   - 云端人物：生成会把提示发给云端。打开开关时要明确告诉用户，并且沿用 P2-2 的确认规矩。
3. **通知**
   - 单独的通知渠道「人物消息」，用户可以在系统里单独关掉；
   - 点通知打开那个人物的对话；
   - 这条消息算人物发的，存进对话历史（沉浸模式）。
4. **安全**
   - 主动消息同样带安全兜底的规矩；
   - 内容不得引导用户熬夜，或者在安静时段回复。

## 范围

- **可以改**：`:hearth`、app 里炉边的页面和设置、WorkManager 任务、通知、清单，以及对应测试。
- **不许碰**：`:llm` 引擎内部、`:net` 白名单、圆桌、发布签名和版本号。

## 验收标准

- [ ] JVM 测试：
  - 时间段和频率上限；
  - 不满足条件就不发；
  - 生成失败不补发；
  - 锁屏隐藏内容；
  - 关掉开关以后，已经排好的任务都取消；
  - 测试模式的人物不发。
- [ ] 真机（用户在场）：
  - 打开开关，把时间调近，充着电等它生成并通知；
  - 点通知进对话；
  - 关掉开关，确认不再发。
- [ ] 截图：设置页、通知（锁屏隐藏和显示两种）、点进去的对话。
- [ ] 全新 worktree 跑门禁，零失败、零警告。

## 风险

- 后台生成耗电、发热。所以只在充电加空闲时生成，并且要实测一次生成耗多少电，写进交付。
- 主动消息一旦太频繁或者时机不对，会招人烦。默认关，并且频率上限保守。

## 审核

- 方案审和全量审必做，复审最多三轮。通过后由统筹合并。
